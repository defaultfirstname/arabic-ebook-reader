Start with the [roadmap](ROADMAP.md) for planned work and the [migration record](GOALS.md#run-the-smoke-tests-locally) for browser test setup.

## Follow a book through the app

1. **Import.** [Book Manager](/apps/web/src/routes/manage/+page.svelte) handles file selection and drops. [Format detection](apps/web/src/lib/functions/file-loaders/book-import-format.ts) supplies the accepted extensions and file picker types. [Loader selection](apps/web/src/lib/functions/file-loaders/load-imported-book.ts) sends EPUB, TXT, and HTMLZ to their own parsers. The parsers return HTML, metadata, and optional blobs and cover. The [import and replication code](apps/web/src/lib/functions/replication/replicator.ts) handles cancellation, saving through the selected storage handler, and refreshing the list.
2. **List and open.** [DatabaseService](apps/web/src/lib/data/database/books-db/database.service.ts) observes storage source and library changes. Book Manager adds local bookmark progress and sorts the cards. The [open operation](apps/web/src/lib/data/storage/book-library.ts) asks the selected handler to prepare the book and returns its local ID. Book Manager navigates to `/b?id=<id>`. A card can refer to an external placeholder, which must be opened from its source.
3. **Read.** The [reader route](/apps/web/src/routes/b/+page.svelte) reads the ID, loads the local record, and handles last-read and sync operations. [Arabic metrics](apps/web/src/lib/functions/book-data-loader/get-arabic-book-metrics.ts) update character counts and can translate a legacy bookmark when its saved offset matches a known paragraph boundary. [Reader content preparation](apps/web/src/lib/functions/book-data-loader/load-book-data.ts) supplies HTML and styles to the paginated or continuous reader.
4. **Bookmark and reopen.** Both modes measure position in the browser and [build the bookmark](apps/web/src/lib/components/book-reader/create-reader-bookmark.ts) from the character count. Continuous mode also saves a scroll coordinate and can reuse it when it still matches the saved character count. The route saves the bookmark by local book ID in IndexedDB. On reopen, the reader loads it and resolves the saved character count to a page or scroll position. The [backup smoke test](apps/web/tests/book-backup.smoke.spec.ts) exercises importing and reopening a book with a legacy bookmark.

## Where PDF fits

The first release will list PDFs alongside other books in the browser library. Existing storage operations look up books by title, including on import, export, and deletion. A PDF and an EPUB with the same title should be able to coexist without sharing a bookmark or affecting each other when deleted. Keep the PDF records outside the title-based operations described above.

- **Import and list.** Detect PDF at the existing import boundary and branch before the HTML loaders. Add PDF metadata and file stores to the existing IndexedDB database so an import can save both together. The metadata store holds a stable PDF ID, title, and page count. Read it for library cards without fetching the original file. Give browser library entries a format and ID so cards and selection can distinguish PDF and HTML books, even if their titles or numeric IDs coincide. Reuse the existing sort rules for the common card fields.
- **Open and resume.** Route PDF cards and the last-opened PDF to the fixed-page viewer before the HTML reader runs. Keep existing `/b?id=<id>` links working and read existing last-opened records as HTML books. Store the PDF's one-based file page and per-book spread preference with its metadata. A layout change should keep the saved page in view. In spread mode, use the saved page to select its containing spread, so switching back to single-page mode can restore that page.
- **Delete and protect existing data.** Delete a PDF's original bytes, card metadata, and saved reading state together. Clear the last-opened pointer if it points to that PDF. Exclude PDFs from the existing ZIP, external sync, and character statistics operations. Test mixed selections so those operations affect only the intended books.
- **Render offline.** Keep navigation and spread pairing in plain TypeScript. Let the browser viewer own rendering and gestures. Bundle the rendering worker with the app and verify that a previously imported PDF can reopen from its direct link while offline.

Prototype the layout before integrating storage. Use a numbered test document with a picture crossing the seam and check both cover pairings, the final unpaired page, and an already-wide scanned page. For library integration, also test a same-title PDF and EPUB, deletion and reopen, the last-opened shortcut, and a fresh restore of the existing ZIP fixture.

For a review, trace an EPUB import, a local reopen from a bookmark, and a legacy ZIP restore. For each flow, find where the local ID is assigned, which data is stored, and how a failure reaches the UI. Then trace a PDF through the proposed boundaries and check where an HTML-only assumption would intercept it.
