[The service worker](apps/web/src/service-worker/index.ts) caches application routes and build assets. It handles query-string book links by looking up the route without the query. Book content and positions are in IndexedDB. Appearance choices are local browser preferences. The [database version definitions](apps/web/src/lib/data/database/books-db/versions/books-db.ts) distinguish schema version 7 from the version 6 record format used by ZIP and external storage. Keep that compatibility boundary when changing storage.

## Reuse and migration

- **Another TypeScript framework.** Move the [card sorting and progress rules](apps/web/src/routes/manage/book-card-rules.ts), [bookmark construction](apps/web/src/lib/components/book-reader/create-reader-bookmark.ts), [progress formatting](apps/web/src/routes/b/format-book-progress.ts), and [PDF spread pairing](apps/web/src/lib/components/pdf-viewer/pdf-spreads.ts) with their types and tests. The bookmark builder has a type-only dependency on the database schema. The web app’s navigation, Svelte stores, and DOM measurements need adapters. The PDF loader can stay on the web with an equivalent worker and asset pipeline.
- **Another platform or language.** Use the current tests as behavior fixtures. Capture Arabic numeric title order and ascending tie-breaks, old bookmark values and character-count conversion, stable IDs by format, one-based PDF positions, both RTL spread pairings, and wide pages that stand alone. Keep representative EPUB, TXT, HTMLZ, PDF, and legacy ZIP inputs with expected outputs. A new platform can provide its own renderer, persistence, and offline cache while preserving those behaviors. Review [Arabic book metrics](apps/web/src/lib/functions/book-data-loader/get-arabic-book-metrics.ts) carefully. It uses a DOM to extract text and remaps legacy positions only when the old offset can be matched.

## Proposed cleanup PRs, in order

1. **Remove the retired DOM subscription helper. Low effort and risk.** `tap-dom.ts` declared `tapDom`, previously used for the text reader’s paper background. The route now owns that background through a component effect. A repository-wide search found the declaration as the sole remaining reference. The route files, PDF dynamic import, and worker asset glob do not load this helper. Remove the file and verify the production build, reader navigation, and offline reopening. The custom-theme schema also carries `selectionFontColor` and `selectionBackgroundColor` from older data. The editor loads and serializes those fields, so retain them until a compatibility decision is made.
2. **Move one PDF import out of Book Manager. Small PR with moderate regression risk.** `onFilesChange` in [Book Manager](apps/web/src/routes/manage/+page.svelte) owns file picking, progress, parsing metadata, copying bytes for transfer to the PDF worker, saving, and cleanup. Move the per-file operation into a PDF import module near `pdf-document.ts`. Keep provider eligibility, mixed-list progress, and error presentation in the route. Preserve the original bytes and cancellation behavior when moving the worker lifecycle. Verify picker and drag-and-drop import, invalid PDF errors, cancellation before save, and reopening a large scanned PDF.
3. **Separate one local library operation from the storage handlers’ mutable context. Moderate effort and higher regression risk.** [The handler factory](apps/web/src/lib/data/storage/storage-handler-factory.ts) caches instances and updates settings on acquisition. [The open operation](apps/web/src/lib/data/storage/book-library.ts), the reader, and replication all set context on handlers. DatabaseService also imports Svelte dialogs and sync settings directly. Start with the Browser DB text-book open path and pass its inputs explicitly. Preserve provider-specific open behavior and defer changes to remote handlers until tests cover their source and cancellation behavior. Verify simultaneous local reads, bookmark and last-opened restoration, legacy ZIP restore, and the v6 IndexedDB upgrade before changing shared storage code.
4. **Tighten the reader and worker boundaries one flow at a time. Moderate effort and higher regression risk.** The text route coordinates navigation, HTML preparation, scrolling, bookmarks, tracking, and sync. Start by giving its existing bookmark builder a small format-independent data type and capturing the offset behavior in fixtures that both modes use. Keep per-mode DOM positioning in the modes. Separately, verify the service worker’s Google Fonts caching branch against a real offline book and custom font before deciding whether it is obsolete. There is no static app font request for it, but imported content can contain runtime resource URLs. Exercise both reader modes, legacy offsets, tracker behavior, and direct offline links before changing either boundary.

The browser suite covers the v6 upgrade, legacy ZIP restore, local text and PDF reopening, RTL input, and mixed libraries. Additional tests most valuable for the proposed work are cancellation during PDF import and overlapping operations on a storage handler. Review the PR order before starting cleanup. PDF backup and restore stays deferred.
